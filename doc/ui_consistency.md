# Panel Next UI 一致性规范

本规范用于 Web、Chrome 扩展及主题包的共同界面基础。目标不是让所有页面长得完全相同，而是让相同层级、状态和操作拥有一致的视觉语义。

## 1. 单一视觉来源

- 颜色、字体、圆角、间距、阴影和动效必须优先使用 `src/themes/tokens.ts` 中的 Theme SDK Token。
- Vue 样式通过 `--pn-*` CSS 变量消费 Token；Naive UI 组件通过 `createThemeOverrides()` 映射同一组 Token。
- 页面组件不新增品牌主色。成功、警告、危险、主操作分别使用 `color.success`、`color.warning`、`color.danger`、`color.accent`。
- 只有内容自身带有语义时才允许使用独立颜色，例如天气状态、图表序列或第三方品牌标识。

## 2. 视觉层级

界面统一使用三层表面：

1. 页面层：`color.pageBackground`，承载壁纸、渐变或纯色背景。
2. 容器层：`color.surface` / `modal.background`，用于卡片、侧栏和弹窗。
3. 交互层：`color.surfaceHover`，用于悬停、选中、分段控件和次级操作。

文字使用三级层级：

- 标题与关键数据：`color.textPrimary`
- 正文与表单标签：`color.textSecondary`
- 说明、占位和时间信息：`color.textMuted`

不要只靠透明度表达不可用或错误状态；状态必须同时包含颜色、文字或图标线索。

### 扩展的磨砂玻璃材质

- 扩展专用规则集中在 `src/styles/extensionGlass.less`，通过 `data-panel-runtime="extension"` 和主题根的 `data-surface="extension"` 隔离，不改变网页端材质。
- 主弹窗约 73% 底色，首页卡片约 60%，内层面板约 30%；从当前主题表面色派生，保留主题主色与文字颜色。只改变底色透明度，不对整个容器设置 `opacity`。
- 独立弹窗、菜单和首页表面使用 28px 背景模糊、适度饱和度、顶部高光与细边框；弹窗内部不重复逐层模糊，也不铺实色页面背景遮住壁纸。
- 设置的管理页面、输入框、表格、图标库和组件库使用同一材质规则；品牌图标与示意预览可保留自身颜色。
- 设备统计、头像预设、历史记录、上传区域及服务器连接表单也使用共享玻璃表面；警告保持语义图标与文字，不因透明背景失去状态辨识。
- 不支持背景模糊或系统设置“减少透明度”时，回退到不透明的明暗表面，保证文字和表单可读；保留组件主题中显式选择的无边框或实色样式。

## 3. 几何与密度

| 用途 | Token | 默认值 |
| --- | --- | --- |
| 小控件、图标底座 | `radius.small` | 8px |
| 输入框、按钮、菜单 | `radius.medium` | 12px |
| 卡片、抽屉、弹窗 | `radius.large` | 18px |
| 标签、状态胶囊 | `radius.round` | 999px |

- 紧凑间距使用 `spacing.compact`，同组控件使用 `spacing.normal`，区块之间使用 `spacing.relaxed`。
- 表单控件默认高度不低于 44px；主要按钮在独立表单中不低于 46px。
- 页面内容宽度由页面壳层管理，子组件不使用固定最小宽度撑破移动端。

## 4. 组件行为

- 主操作：每个视图保持一个明确主按钮，使用主题主色。
- 次操作：使用描边或中性表面，不与主操作争夺层级。
- 危险操作：必须使用危险语义并在不可逆时二次确认。
- 输入框：标签常驻，placeholder 只提供示例或简短提示，不能替代标签。
- 弹窗：标题、内容、操作区顺序固定；圆角和表面由共享弹窗组件管理。
- Web 与扩展的管理弹窗挂载在 `.pn-theme-root` 内，确保传送出来的子页面也继承同一套主题变量。
- 管理应用统一使用 `pn-app-page`、`pn-app-card`／`pn-app-panel`、`pn-app-heading`、`pn-app-actions` 与 `pn-app-empty`；不要在每个页面重写深浅两套卡片颜色。
- 状态提示：成功、警告、错误消息使用全局消息系统，不在页面里重复发明样式。
- 组件库预览只展示示意内容，必须明确标注“样式预览”；真实数据仅在添加后的组件中请求。已添加状态同时以文字和数量呈现，不只改变颜色。
- 访客可编辑保存在当前浏览器的小组件与布局；需要写入账号的书签新增、编辑和删除才要求登录。添加组件的成功提示必须等本地保存完成，保存失败要恢复当前页面的已持久化布局。
- 图标库使用内置品牌色与矢量图展示候选项，选择后也优先保存内置图标；保存前允许编辑名称、网址、图标类型和背景色。已有远程图片未加载或加载失败时，立即显示内置站点标识或可辨认的文字图标，不显示破图。
- 图片类书签图标优先读取浏览器本地 Cache Storage；只在首次缓存缺失或用户更换图片时下载，离线或下载失败则继续显示上述备用标识。缓存并非独立备份，用户清除浏览器数据时可被移除。

## 5. 可访问性与响应式

- 键盘交互元素必须保留清晰的 `:focus-visible` 焦点环。
- 文本和背景保持可读对比度；浅色和深色模式都必须单独检查。
- 遵循 `prefers-reduced-motion`，非必要动画在减少动态效果时关闭。
- 以 390px、768px、1280px 三个宽度作为基础检查点；移动端操作区允许纵向排列。
- Web 控制中心在手机尺寸使用覆盖式侧栏；展开菜单不能压缩表单内容，选择页面或点击遮罩应收起菜单。
- 组件库在窄屏中让目标页面和搜索框分行，分类横向滚动，预览卡片单列显示，避免缩小输入区。
- 图标按钮必须提供可访问名称，装饰图片使用空 `alt`。

## 6. 提交前检查

- 新增样式是否可由现有 Token 表达。
- Web 与扩展是否消费同一语义，而非复制颜色常量。
- 明暗模式、键盘焦点和 390px 宽度是否可用。
- `type-check`、响应式校验、主题注册表校验以及 Web/扩展构建是否通过。

## 7. 后续收敛顺序

1. 将管理应用中的重复卡片、标题和操作区收敛为共享页面壳层。
2. 统一首页分组标题、悬浮操作和编辑状态，移除零散硬编码颜色。
3. 统一空状态、加载状态、错误状态和确认流程。
4. 为关键页面补充桌面、移动端、浅色和深色视觉回归基线。

## 8. 扩展设置收尾验收（2026-09-30）

- 在本地扩展入口预览检查个人中心、搜索栏、时间与日期、主题与壁纸、小组件与布局、侧边栏、图库素材中心、备份与恢复、服务器节点连接、Docker 容器管理、系统与站点配置、关于与版本信息，共 12 个分区。
- 1280×720 浅色、1280×720 深色、390×844 深色均逐页截图检查；文档宽度分别保持 1280px 和 390px，无整页横向溢出。窄屏导航保留有意的横向滚动。
- 设备统计和上传区域的实测底色透明度约 44%，主设置容器约 73%；内层内容画布透明。主题中心描述已补齐中英文翻译，取消关闭未保存设置。
- 本地预览使用 Chrome 存储与权限替身，不能代替真实扩展权限、持久化及重启验收；没有执行账号资料保存、布局回滚、服务器切换或文件清理。
- Docker 后端报告 Engine 不可用，仅验证错误状态界面；未验证容器控制。
- 原生 Chrome 已安装 iTab，未安装 Panel Next；保留现有新标签页。加载本地测试扩展并临时替换新标签页需要用户确认后再验收。
